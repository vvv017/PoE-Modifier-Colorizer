# PoE 詞綴上色器 / PoE Modifier Colorizer

Windows x64 的 PoE 1 獨立客戶端英文／繁體中文詞綴編輯器。Release 套件內含
.NET 8 執行環境；自行建置的 framework-dependent 版本需安裝 .NET 8 Windows
Desktop Runtime。程式資料夾必須可寫入，請勿放入遊戲目錄。

**目前為開發版本。** 已通過本地編譯、資料匯入及一次 GGPK 套用後的資源讀回核對；
遊戲內呈現仍需確認。單實例處理會嘗試喚回原視窗，Windows 拒絕切換前景時
閃爍工作列。桌面曾出現啟動與回應問題，完整互動尚未完成驗收。
詳見 [驗證紀錄](HANDOFF.md)。

此儲存庫提供原始碼，不包含遊戲資料、個人設定、撤銷紀錄或原生 codec。

## 下載

在 [v0.1.3 Release](https://github.com/vvv017/PoE-Modifier-Colorizer/releases/tag/v0.1.3)
下載 `PoE-Modifier-Colorizer-0.1.3-win-x64-complete.zip`，解壓縮整包後開啟
`GgpkColorizer.exe`。保持 EXE 與 `oo2core.dll` 在同一個資料夾。
套件包含原始碼與第三方授權說明，不包含個人配色、詞綴清單或撤銷紀錄。
從舊版升級時，先關閉程式，再將套件覆蓋到原資料夾；保留原有 `data` 資料夾，
才能保留配色及還原已套用顏色所需的紀錄。

Oodle 是獨立的專有元件，不適用本專案的 AGPL 授權；其再散布權及與 AGPL
元件的相容性尚未確認，免費提供不代表已取得授權。

## 使用

1. 開啟 `GgpkColorizer.exe`。平時只載入 `data/` 的本機清單、配色與比對結果。
2. 首次使用或每賽季按「更新本季詞綴清單」。同季遊戲更新後也可重按。
   這會唯讀匯入所選 `Content.ggpk`，保存完成後再與 PoEDB 比對。
3. 在「遊戲文字」選擇繁體中文或英文，再以分類或該語言的關鍵字找詞綴。
   按 Ctrl / Shift 可選多項，選色後按
   「設定選取詞綴」保存配色。此步不修改遊戲。
   選「紅藍王祭壇」後，可再篩選紅／藍王、玩家／異界小怪／頭目與正面／負面。
4. 關閉遊戲與啟動器，再按「套用選取項目」或「套用所有語言的已設定項目」。
   套用全部涵蓋兩種語言，不受目前搜尋、分類或遊戲文字篩選影響。
   首次請只套用一條，進遊戲確認顏色。預覽是近似色，不代表遊戲已驗證。
5. 若要移除已套用的顏色，保持遊戲與啟動器關閉，在詞綴頁選取項目後按
   「清除並還原」。即使顏色欄已空白，曾用舊版「清除顏色」的項目仍可選取還原。
   程式核對目前 GGPK 內容及自身紀錄；確認還原成功或文字已是原文後，才清除配色設定。
6. 在「改動紀錄」撤銷選取紀錄或最近一批。同一詞綴先撤銷最近一次改動。

「清除並還原」本身會寫入 GGPK，因此操作前也必須關閉遊戲與啟動器。
「介面語言」只切換按鈕文字；「遊戲文字」決定要查看、搜尋和設定哪種語言的詞綴。

### 雙語配色

英文與繁體中文的配色分開保存。第一次讀取含繁中的清單時，程式只把來源檔、
Stat ID 與數值條件唯一對應的既有英文配色複製到繁中，不按翻譯行號猜測。
早期舊鍵另須有與目前原文完全吻合的自身歷史紀錄才能對應。
原有設定及歷史紀錄全部保留；後續匯入不會重新複製或覆蓋你調整、清除的繁中規則。
無法唯一對應的項目可直接在繁中清單設定。繁中使用 GGPK 內建原文，不自行翻譯。

### 祭壇數值與作用範圍

物理傷害減免與護甲的「減少」和「增加」分開列出、分開保存配色。選擇玩家的
物理減傷減少，不會替怪物或頭目的物理減傷增加上色；零值保持原文。
這兩項連同火、冰、閃電、混沌抗性、閃避值及每顆暴擊球的暴擊加成，共八種
屬性使用祭壇專用描述，不把祭壇配色寫進裝備等場景共用的文字。
四抗、閃避及每顆暴擊球暴擊加成只提供負值分支；非負值維持原文。
英文與繁中各自遵守相同的作用範圍。

「負面」是祭壇代價，不代表原始數值一定小於零。增加藥劑消耗、受到持續混沌
傷害、遭受異常狀態的機率等仍是負面效果，保留遊戲原有的正值條件。
描述中的 `reduced` 或「減少」也可能透過格式轉換顯示負值的絕對值。
請一併查看作用對象與預覽，不用數字正負猜測效果。其他共用詞條的跨場景
行為保持原樣；這八種屬性的局部描述優先序仍需遊戲內確認。

更新清單會把這八種屬性的舊共用配色搬到祭壇負值規則；正值項目不會自動沿用。
匯入不修改 GGPK。套用時，程式只在目前共用上色與自身歷史紀錄完全吻合時
還原它，再加入祭壇描述。無法確認來源或區塊已有其他修改時會停止整批寫入。
全域上色的舊紀錄保留並標為已撤銷。撤銷以完整屬性區塊為單位；同一屬性的
正負分支及兩種語言，都須先撤銷最近一次區塊改動。同次套用會合併紀錄，保存
各條規則的前後內容。撤銷最初新增的描述會移除區塊，不重新上色共用文字。
舊版英文祭壇抗性區塊仍可讀取；撤銷繁中升級會恢復記錄中的原區塊。

## 清單與比對

- 指定讀取地圖、祭壇描述檔及其 include，沒有全封包文字搜尋。
  祭壇另讀本地 AtlasPrimordialAltarChoices、ChoiceTypes、Mods、Stats 資料表，
  依 Stat ID 與數值條件找回共用文字，包含小怪掉落、玩家懲罰及怪物增強。
  共用檔只保留 `map_*` 或祭壇實際引用的描述，避免混入所有技能、裝備文字。
  清單仍可能包含歷史或隱藏詞條，不等於當季可隨機出現的詞綴名單。
- 紅藍王、玩家／異界小怪／頭目、正面／負面來自本地祭壇選項及 Mod ID。
  同一文字可有多種用途，也可同時屬於地圖和祭壇；篩選不會建立重複寫入目標。
  有些舊版或 Ruthless 詞條仍在遊戲資料中，來源提示會保留這項限制。
- 共用描述也可能在其他場景顯示；來源檔案和 Stat ID 可在預覽中查看。
- PoEDB 是提示來源。本地詞條才是編輯依據，差異或網路失敗不阻止操作。
  目前只比對英文頁面，繁中顯示未完成，不套用英文的比對結果。
- 網站候選依相同陣營、對象與正負效果匹配。文字模板相符不代表網站 Mod ID
  或數值範圍已核對；網站缺少陣營的列會略過並提示，不用文字猜陣營。
  無法可靠對應時明確標示候選、無法對應或未完成。
- 配色按穩定識別碼保留。更新後消失的詞條設定仍留在 `settings.json`；
  只有目前清單內可定位的項目能套用。

## 資料與撤銷

`data/settings.json` 保存路徑、語言與配色；`catalog.json` 保存本機清單；
`comparison.json` 保存綁定清單版本的 PoEDB 報告；`changes.json` 保存改動紀錄，
另保留一份小型 `changes.json.bak`。若 JSON 損壞，程式會停止載入並指出檔案位置；
不會自動把舊紀錄當作完整現況。這份 JSON 副本不是 GGPK 備份。
搬移程式時一起保留整個 `data` 資料夾，否則會失去配色與撤銷依據。

程式不建立 GGPK 備份或工作副本。寫入前保存每項精確原文、新文、定位資料與
資源雜湊，再寫入、保存索引並重開讀回。普通配色只修改選定語言的文字片段；
祭壇數值隔離另外保存完整前後區塊，複製原有各語言描述並拆分英文與繁中的數值條件。
BOM、換行、未選文字及數值占位符保持不變。

撤銷會先核對目前文字；遇到更新或其他工具造成的衝突就略過，不用舊文字覆蓋。
未完成的寫入紀錄會在下次手動匯入、套用或撤銷時核對，不在啟動時打開 GGPK。
撤銷只恢復詞條內容，不縮小封包或恢復原始二進位排列。中斷寫入仍可能損壞封包，
此時可能需要官方客戶端修復；逐項紀錄無法代替完整封包復原。

## 建置

使用 .NET SDK 8：

```powershell
dotnet restore GgpkColorizer.csproj --locked-mode
dotnet build GgpkColorizer.csproj -c Release --no-restore
dotnet publish GgpkColorizer.csproj -c Release --no-restore --self-contained false -o publish
```

將相容的 x64 `oo2core.dll` 放在 `publish/GgpkColorizer.exe` 旁。
本地驗證使用的 codec 來自
[LibGGPK3 v2.7.5 工具包](https://github.com/aianlinb/LibGGPK3/releases/tag/v2.7.5)。
codec 必須另行取得並遵守其授權，本儲存庫不提供該二進位檔。
